# Architecture — JotList

Decided with the owner in design interviews on 2026-11-14 (architecture, then UI review). This is the agreed architecture for the MVP in [README.md](../README.md). The UI design is in [docs/design/](design/) (11 desktop screens); §15 records the decisions made while reviewing it.

Decisions marked **(owner)** were made by the owner. Decisions marked **(default)** are non-functional choices the owner delegated; change them freely if a better reason appears, and note it here.

## 1. Product context
- **App name:** JotList. **URL:** `https://jotlist.eukron.com` (zone `eukron.com` is on the owner's Cloudflare). Repo stays `todo-list-demo`. **(owner)**
- A **real public app**, not a throwaway demo: anyone who watches the video can sign up and use it. The video shows the finished result. **(owner)**
- **Thai-only UI**, but every string lives in an i18n file (`th`) so another language can be added later. **(owner)**
- Responsive web app + **PWA** (installable). No native apps. **No offline mode** in the MVP. **(owner)**
- Has a **delete-account** button and a **privacy page**. **(owner)**
- Code is written by the Software Engineer bot and reviewed by the owner. **(owner)**

## 4. Data model
All ids are **UUIDv7 generated by the client**, so creates are idempotent (a retried create with the same id is a no-op) and optimistic UI never waits for a server id. All timestamps are UTC epoch milliseconds set by the server.

Better Auth owns `user`, `session`, `account`, `verification`. App tables:

**user_settings** — `user_id` PK, `display_name`, `avatar_key` (R2 key, nullable), `timezone` (IANA, default from the browser at sign-up), `theme` (`light|dark|system`, default `system`), `start_page` (`today|inbox`, default `today`), `week_start` (`sun|mon`, default `mon`), `digest_enabled` (default false), `digest_time` (`HH:MM`, default `08:00`), `digest_sent_on` (`YYYY-MM-DD`), `onboarded_at`.

**projects** — `id`, `user_id`, `name` (≤ 50 chars), `color` (one of `blue|orange|violet|green|black`, the 5 design swatches; **no icon**), `position`, `created_at`, `updated_at`, `deleted_at`.

**tasks** — `id`, `user_id`, `project_id` (null = Inbox), `title` (≤ 500), `notes` (≤ 10,000), `priority` (`none|low|medium|high`, default `none`), `due_date` (`YYYY-MM-DD`, user's local date), `due_time` (`HH:MM` local, nullable), `remind_at` (UTC ms, derived), `reminder_sent_at`, `position`, `completed_at`, `created_at`, `updated_at`, `deleted_at`.

**subtasks** — `id`, `task_id`, `user_id`, `title` (≤ 500), `completed_at`, `position`, `created_at`, `updated_at`, `deleted_at`. A separate table, so "one level only" is enforced by the schema: a subtask has no children.

**attachments** — `id`, `task_id`, `user_id`, `r2_key`, `mime`, `bytes`, `width`, `height`, `position`, `created_at`, `deleted_at`. See §16.

**push_subscriptions** — `id`, `user_id`, `endpoint` (unique), `p256dh`, `auth`, `created_at`.

Indexes: `tasks(user_id, updated_at)`, `tasks(user_id, completed_at)`, `tasks(remind_at) WHERE reminder_sent_at IS NULL`, `projects(user_id, updated_at)`, `subtasks(task_id)`.

### Rules
- **Active task** = `completed_at IS NULL AND deleted_at IS NULL`. Max **1,000 active tasks per account** **(owner)**. Creating the 1,001st returns `409 TASK_LIMIT` with a Thai message; the client rolls back the optimistic add. Restoring or un-completing a task also counts against the limit. Defaults: max 100 projects, max 50 subtasks per task.
- **Soft delete** (`deleted_at`) so Undo works; a daily cron hard-deletes rows deleted more than **7 days** ago **(owner)**.
- **Dates and time zones** **(owner)**: due date/time are stored as the user's local wall-clock values; `remind_at` is computed on the server from `due_date + due_time + user_settings.timezone` and recomputed when any of those change. Today / Upcoming are computed from "today" in the user's time zone.
- **Ordering:** `position` is a fractional-index string; moving an item writes only that row. Moving a task to a project puts it at the end of that project.
- **Views:** Inbox = `project_id IS NULL`; Today = due today or overdue, not completed; Upcoming = due tomorrow through 7 days ahead, grouped by date (default reading of "next 7 days", since today already has its own view); Logbook = completed, newest `completed_at` first, **paged 50 at a time** **(owner)**, unlimited history.

## 5. API
JSON over HTTPS under `/api`, all Zod-validated, all queries scoped by the session's `user_id` (never trust a `user_id` from the client).

- `/api/auth/*` — Better Auth handler.
- `GET /api/sync?since=<ms>` — every task, project and subtask of the user with `updated_at > since`, **including soft-deleted rows** (tombstones), plus a new `cursor`. `since` omitted = full load of active data + projects. Logbook items are not part of the full load.
- `GET /api/logbook?before=<completed_at>` — completed tasks, 50 per page.
- `GET /api/search?q=` — `LIKE '%q%'` on title and notes, scoped by `user_id`, max 50 results, active + completed. **No FTS5**: SQLite FTS5 cannot segment Thai, so it would miss words in the middle of a Thai sentence **(owner)**.
- `PUT /api/tasks/:id` (create-or-update, idempotent), `PATCH /api/tasks/:id`, `DELETE /api/tasks/:id` (soft), `POST /api/tasks/:id/restore`. Same shape for `projects` and `subtasks`.
- `POST /api/tasks/:id/attachments` (multipart), `GET /api/files/:key` (owner-checked stream from R2, `Cache-Control: private`), `DELETE /api/attachments/:id`; `PUT /api/me/avatar`, `DELETE /api/me/avatar`.
- `POST /api/tasks/reschedule-overdue` (moves every overdue active task to today; returns the previous dates so Undo can restore them).
- `POST /api/push/subscribe`, `DELETE /api/push/subscribe`.
- `PATCH /api/settings`, `DELETE /api/account` (hard-deletes the user and every row they own).

Errors use one shape: `{ "error": { "code": "TASK_LIMIT", "message": "<Thai text>" } }`.

**Conflicts:** last write wins on `updated_at` (server time). Good enough for a single-user app; no merge logic.

## 6. Sync between devices — no realtime **(owner)**
- TanStack Query refetches `/api/sync?since=cursor` **when the tab/app regains focus** and **every 30 s while the page is visible**; polling stops when the tab is hidden.
- Delta sync keeps each poll tiny; tombstones remove deleted items on other devices.
- While a mutation is pending, polling for the affected data is paused so a poll cannot overwrite an optimistic change.
- Expected result: another device catches up within 30 s, or instantly when switched to.

## 7. Optimistic mutations and Undo
- Every mutation updates the TanStack Query cache first, then calls the API; on error it rolls back and shows a Thai toast.
- Complete and delete are sent to the server immediately. **Undo (5 s)** sends the reverse mutation (`uncomplete` / `restore`), so nothing is lost if the tab closes during the toast.

## 8. Authentication
- **Email/password** with **required email verification**: an account cannot sign in until its email is verified. Password reset by email. Both emails via Resend. Turnstile on sign-up and forgot-password. **(owner)**
- **LINE login** via Better Auth's LINE provider, requesting the `email` scope. ⚠️ The owner must apply for **email permission** in the LINE Developers Console first.
- **Account linking by email** **(owner)**: the same email = the same account.
  - LINE sign-in with an email that belongs to a verified email account → linked into that account.
  - Because unverified email accounts cannot sign in and hold no data, an unverified pending sign-up with the same email is replaced by the LINE account. This blocks pre-registering a victim's email to take over their account.
  - Email sign-up with an email already owned by a LINE account → "this email already has an account; sign in with LINE, or use forgot-password to set a password".
  - LINE sign-in without an email (user declined, or no email on LINE) → a separate LINE-only account.
- Sessions: Better Auth cookie sessions, `HttpOnly`, `Secure`, `SameSite=Lax`; Better Auth's origin check covers CSRF.

## 9. Reminders — Web Push only **(owner)**
- Only tasks with a **due time** get a reminder, **at** the due time. No custom offsets in the MVP. Email reminders are post-MVP.
- **Cron Trigger every 1 minute**: select tasks with `remind_at <= now`, `reminder_sent_at IS NULL`, not completed, not deleted (batches of 500). Set `reminder_sent_at` **before** sending, so a crash never double-sends. Send Web Push with **VAPID signed via WebCrypto** (the Node `web-push` library does not run on Workers). A `404/410` from the push service deletes that subscription.
- Changing due date/time clears `reminder_sent_at`. A reminder may arrive up to ~1 minute late.
- The service worker shows the notification; tapping it opens the task.
- Note: on iPhone, Web Push works only after the PWA is added to the home screen (iOS 16.4+). The app should tell iPhone users this when they turn on reminders.

- **Daily digest** **(owner)**: optional push once a day at the user's `digest_time` (local), "today N tasks, overdue M"; off by default. The same 1-minute cron checks users whose local time has passed `digest_time` and `digest_sent_on` < today.

## 10. Abuse protection and limits **(owner)**
- Rate limits (Workers Rate Limiting binding): **auth 20 requests/min per IP**, **API 120 requests/min per user**. Over the limit → `429` with a Thai message.
- Turnstile on sign-up and forgot-password; Resend free tier is 100 emails/day, so this protects the quota.
- Input size limits are enforced by the shared Zod schemas (see §4).

## 11. Non-functional targets (default)
- API p95 < 300 ms at the edge; `/api/sync` delta response < 50 KB typical.
- Frontend: initial JS ≤ 250 KB gzipped; LCP < 2.5 s on a mid-range phone over 4G; route-level code splitting.
- Accessibility: keyboard-usable Quick Add, task list and dialogs; visible focus; colour contrast AA in both themes.
- Security headers on every response: CSP (self + Turnstile), `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`.
- Observability: Workers Logs on; one structured log line per error with request id; no personal data (emails, task text) in logs.
- Backups: D1 Time Travel (point-in-time restore).

## 12. Environments and deploy **(owner)**
- **Local:** `wrangler dev` / Vite dev server with a local D1. Secrets in `.dev.vars` (never committed; `.dev.vars.example` is).
- **Production:** `jotlist.eukron.com`. No staging.
- **Deploy:** GitHub Actions on push to `main` → install, type-check, test, `wrangler d1 migrations apply --remote`, `wrangler deploy`. `develop` does not deploy. Cloudflare API token and app secrets live in GitHub Actions secrets and Worker secrets.
- Secrets: `BETTER_AUTH_SECRET`, `LINE_LOGIN_CHANNEL_ID/SECRET`, `RESEND_API_KEY`, `TURNSTILE_SECRET_KEY`, `VAPID_PUBLIC_KEY/PRIVATE_KEY/SUBJECT`.

## 16. Images (task attachments and profile photos) **(owner: R2; limits are defaults)**
- Images only: jpeg, png, webp, heic/heif (checked by magic bytes, not just extension). The client downscales to max 2048 px on the long side and re-encodes to WebP before upload (HEIC: browsers that cannot decode it upload the original).
- Limits: 5 MB per file after processing, 10 images per task, 200 MB per account (sum of `bytes`). Over a limit → `413`/`409` with a Thai message.
- R2 bucket is private. Keys: `u/<user_id>/t/<task_id>/<attachment_id>` and `u/<user_id>/avatar/<uuid>`. Files are only served through `GET /api/files/:key` after checking the key's owner.
- Where: a gallery under the notes in TaskDrawer (file picker, drag-and-drop, paste); click opens a full-screen viewer; task rows show 📎 + count. Images can also be pasted into Quick Add and upload right after the task is created.
- Deleting a task soft-deletes its attachments; the 7-day purge cron deletes the R2 objects too. Deleting the account deletes every R2 object under `u/<user_id>/` immediately.
